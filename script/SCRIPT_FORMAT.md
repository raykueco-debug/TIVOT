# 餵稿規格 — Ray 寫稿 → 我轉成可播的劇情

> ver -342 定案。**這份是給 Ray 看的**：你要怎麼寫、寫到什麼程度我就不會回頭問你。
> 引擎那一側的欄位規格在 `modules/story.js` 的「演出層」註解，兩邊要一起改。

---

## 0. 一句話

**你寫「拍」，我轉 JS。** 你只要交代「這一拍畫面上發生什麼、誰在說話、說什麼」，
其餘（站位、明暗、立繪大小、檔案路徑、預載、打字速度）全部是引擎的事，
你不用寫、也**不要**寫 —— 寫了反而會與既有規則打架。

---

## 1. 稿子的最小單位是「拍」，不是「句」

一拍 ＝ **玩家點一下畫面推過去的一個單位**。它可以是：

| 種類 | 長什麼樣 |
|---|---|
| 對白拍 | 有人講話，出對話框 |
| 演出拍 | 沒有台詞（咆哮、掃射、換場），**不出對話框**，玩家點一下推過去或自己走完 |
| 情境卡拍 | 背景上蓋半透黑＋置中大字（時間地點），不出對話框 |
| 閘門拍 | `讀取 下一場景` / `戰鬥 tutorial` —— 不是演出，是流程交棒 |

**空行分拍。** 一段文字＝一拍，不必編號。

---

## 2. 格式

```
場景 dungeon_chase → dungeon_lunaria
旗標 dungeon_cleared          ← 選填，這一段播完要記住的事
進度 1                        ← 選填，setStage

> 背景 HolyseeDungeonWhole
> 音樂 crisis
> 卡片 1908年6月13日 / 聖王廳地宮　G2 區

諾薇兒(跑)：追、追上來了！
> 音 se_steps

諾薇兒(畏縮)：啊！
> 抖  音 se_Fall

諾薇兒：別管我！你快走！
> 插圖 001_Nouvelle_Fell  平移 上
> 等平移跑完再出框

諾薇兒：你……！
> 音 se_weapon_reload ×2 隔 0.5 秒

> 戰鬥 tutorial
```

規則只有三條：

1. **台詞行**＝`角色(差分)：內容`。差分可省；括號裡中文英文都行（我對照 `speakers.js`）。
2. **演出行**＝以 `>` 開頭。一拍可以有好幾行，也可以擠在同一行。
3. **沒有台詞行的拍**就是演出拍／卡片拍／閘門拍。

主角名寫 `{P}`（顯示時才代換成玩家取的名字，預設「托爾斯」）。

## 3. 演出詞彙表

你寫左邊，我轉右邊。**用你順手的說法寫就好** —— 這張表是「引擎做得到什麼」的清單，
不是要你背的語法。表上沒有的東西 → 我會回你「這個目前做不到，要不要改成 ○○」。

| 你寫 | 意思 | 引擎欄位 |
|---|---|---|
| `背景 X` / `背景 收` | 換背景。插圖也能當背景（寫 `002_SaintAssult`） | `bg` |
| `插圖 X` / `插圖 收` | 全屏插圖，蓋在立繪**之上** | `cg` |
| `平移 上` / `平移 下` | 插圖平移 2.6 秒。**上＝由下往上**（終點在上方） | `cgPan` |
| `背景平移 上/下` | 同上，但動的是背景 | `bgPan` |
| `放大 1.18` | 插圖**直接**放大這個倍率（不做放大動畫），要動就再配 `平移 上` | `cgScale` |
| `推近 臉` | 以臉為中心**緩慢放大**的過程（座標我去量） | `cgZoom` |

> ⚠ `放大` 與 `推近` 二選一。滿版插圖上**會動的縮放容易被讀成畫面在抖**（`-339` 踩過），
> 所以現行 003 走的是「直接放大 ＋ 由下往上移到頂」。
| `CI X` / `CI 收` | 暗調 CI 插入（`resources/SI/` 的圖） | `ci` |
| `卡片 文字` | 情境卡。要換行寫 `/` | `card` |
| `音樂 X` / `音樂 停` | BGM，持續到下次改變 | `bgm` |
| `音 X` | 音效。要多發寫 `×2 隔 0.5 秒` | `se` |
| `抖` | 畫面抖一下（對話框不抖） | `shake` |
| `掃射` | 插圖上灑兩秒的機槍命中點＋連續抖動 | `fx:'gunfire'` |
| `暗調` | 這一句說話者的立繪壓成剪影（還沒表明身分） | `dark` |
| `退場 A、B` | 請人下台。**立繪是持續狀態，不寫她就一直站著** | `hide` |
| `等 2.6 秒再出框` | 對話框延後出現，讓演出先跑完 | `delay` |
| `自動 3.5 秒` | 這一拍自己走完，不等玩家點 | `auto` |
| `讀取 下一場景` | 插一頁標準讀取頁，把素材抓完再往下演 | `load` |
| `戰鬥 tutorial` | 交棒給戰鬥（會先演 Kerberos 之門） | `battle` |

**目前做不到的**（要就得先開工，不是改稿能解的）：語音對白、立繪在畫面上走動、
對話選項分歧（主線是純線性，分歧靠「去哪裡找誰」）、插圖左右平移、
`掃射` 以外的畫面特效。

## 5. 一定要交代清楚的六件事

這六件是這幾版**反覆咬人**的地方 —— 稿子沒寫我就得回頭問你，寫了就一次到位。

1. **這一拍畫面上有誰。** 立繪、背景、插圖全是**持續狀態**：不明講「收掉／退場」，
   上一拍的東西會一直留著。「那個人怎麼還站在那裡」幾乎都是這個。
2. **插圖什麼時候收。** 插圖在立繪**之上** —— 只要這一拍要看到人，插圖就得先讓開
   （或改成當背景用）。
3. **平移的終點是重點。** 「由下往上」會**停在上方**。跌倒的構圖往下平移會停在裙底。
   你只要說「要收在臉上」我就知道方向。
4. **沒有台詞的拍要不要自己走、走多久。** 沒有對話框就沒有 `▼` 提示，
   停在那裡看起來像當機。通常是「配合聲音長度」——**告訴我配哪支聲音**就行。
5. **對話框要不要等演出跑完再出。** 平移 2.6 秒、立繪滑入 0.45 秒，
   要「等她跌完再講話」就講一聲。
6. **新素材的檔名。** 沒有檔名我沒辦法接（見下一節）。

## 6. 這些**不要**寫

- 站位（左右）、明暗、立繪大小與位置、腳落在哪 —— 全部是算出來的，寫死會壞掉。
- 檔案路徑與副檔名 —— 給名字就好。
- 預載、轉場黑幕、打字速度、`▼` 提示 —— 引擎自己處理。
- `pos`／`when`／`requires`／好感門檻 —— 主線**不讀**這些（單向資料流：主線寫、其餘讀）。

## 7. 新素材的交付規格

| 類型 | 放哪 | 命名 | 尺寸 |
|---|---|---|---|
| 對白立繪／差分 | `resources/SI/` | `角色_SI_變體.webp` | **1024×1536 全身** |
| 全屏插圖 | `resources/illustration/` | `NNN_描述.webp`（三位數開頭） | 直式滿版 |
| 背景 | `resources/background/` | `地點名.webp` | 直式滿版 |
| 音效 | `resources/audio/se/` | `se_分類_名稱` | — |
| BGM | `resources/audio/bgm/` | `bgm_場合` | — |

- 圖一律轉 WebP（`cwebp -q 80`，有透明加 `-alpha_q 100`），原始檔進
  `resources/_originals/`（不入版控）。
- ⚠ **立繪差分要是全身**：半身/胸像照 alpha 邊界量會把人放大好幾倍。
  每張新圖的取景值（頭頂 / 腳底 / 臉中心）我會**逐張重量** —— 沿用上一張一定歪。
- ⚠ 音效加進資料夾後我要同步 `story.js` 的表；漏了 `tools/script_lint.py` 會報。

## 8. 場景鏈

```
場景 A → B      A 播完接 B
場景 C → 結束    鏈到此為止，控制權交還（回首頁／回上一層）
```

- `旗標 xxx`＝這一段播完寫進存檔的一次性記號（其他系統只讀不寫）。
- `進度 N`＝setStage，推進主線階段（會影響閒聊聽得到什麼）。
- 場景之間要插讀取頁就在該拍寫 `讀取 下一場景`；
  **開場那一頁已經把整條鏈預載完**，短鏈不必插。

## 8.5 敵人資訊標準卡（ver -375，Ray 定的格式）

劇情中間插一場戰鬥時，那隻怪照這張卡交：

```
> 戰鬥 guild_hunter          ← 拍上寫這一行，卡另外附

[敵人名：賞金獵人
 背景：Captal_Guild_Day        ← 戰鬥時身後那張圖（去背立繪一定要給）
 戰鬥立繪：NPC_GuildHunter_SI_Attack
 HP：200
 延時懲罰 5 秒，攻擊力 5，彈孔特效     ← 幾秒沒點就挨打／挨多少／什麼特效
 點錯懲罰攻擊力 5，鈍器受擊特效
 蓄力攻擊：10，大彈孔特效              ← 紅點那一發（大絕）
 抗性：無
 弱點武器：無
 盤面配置：33344, loop                 ← 3＝九宮格、4＝16 宮格；loop＝打完一輪從頭再來
 掉落物：黃銅彈殼 x6                   ← 固定掉，不擲骰
 金錢：HP 的 6~8 成隨機
 這一場不能用聖徒化與伙伴技]           ← 有這條就寫，沒寫＝可以用
```

轉成 `config.js` 的 `enemies.<id>`（怪本身的數值）＋ `battles.<id>`（這一場的規則）。
同一隻怪之後在別的場次登場時**卡不用再抄一次**，腳本寫同一個 id 就好。

- ⚠ **抗性／弱點目前還沒實作** —— 資料照樣存進去（`resist`/`weak`），程式後補。
  卡上有的欄位不要因為「還沒做」就省略。
- ⚠ 受擊特效目前有：`彈孔`（玻璃碎裂，可大可小）／`鈍器`（不見血的衝擊環）／
  `爪痕`／`血痕`／`齒痕`／`刀痕`。要新的就說，我加。
- ⚠ 打**輸**了會走一般的失敗流程（回主畫面），那一段對白的旗標是「演完才記」，
  所以回頭再走一次還會再打。要改成「當場重來」再說。

## 8.6 空畫面拍

`（空畫面無立繪）音 se_xxx` ＝ **沒有對話框、沒有人**，只有背景與聲音。
轉成 `{ speaker:'PLAYER', text:'', auto:900, se:'…', hide:[…] }`：
空台詞本來就不出框（ver -327 的規矩），`hide` 負責把台上的人請下去。

⚠ 與**空白對話框**（`（主角說話空白頓點）`）是兩回事：那個是「他開口了但沒有台詞」，
框要出、裡面沒字（`blank:true`）。差別在**畫面上有沒有人在說話**。

## 9. 我收到稿之後會做什麼

1. 轉成 `script/mainScript.js` 的 line 物件，**逐拍寫上你交代的意圖**（為什麼往上平移、
   為什麼這裡要收插圖）—— 那些註解是下一輪不再踩同一個坑的唯一保險。
2. 跑 `python3 tools/script_lint.py`：檢查角色 id、差分、背景／插圖／CI、音效／BGM、
   scene 鏈、空拍沒有 auto…… 缺什麼一次列出來。
3. 在 390×844 實跑一遍，回報：**哪幾拍缺素材**、**哪幾拍我改了你的寫法以及為什麼**。
4. commit，回寫 `HANDOFF.md`。

## 10. 最省事的餵法

**直接照你原本的寫法寫散文稿也行** —— 地宮那一幕就是這樣來的。
你寫「她跌倒，插圖進來，鏡頭收在臉上，這時候她喊『別管我』」，我拆成拍。
差別只在：**上面第 5 節那六件事你沒講，我就會回頭問你**，來回一趟。
