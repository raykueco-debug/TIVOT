## 二、載入（照 `helmArt` 的寫法）

```js
const deckArt={ deck:null, sky:null };
(function loadDeck(){
  const one=(k,src)=>{ const im=new Image(); im.onload=()=>{deckArt[k]=im;}; im.src=src; };
  one('deck','Deck_day.webp'); one('sky','Sky_day.webp');
})();
```

## 三、畫在哪（`drawPanel` 裡，漸層填完之後、`Base` 之前）

```js
  /* 甲板背景：天空層（捲動）→ 甲板層（不動）。兩層都在基座與舵輪之後。 */
  if(deckArt.deck){
    ctx.imageSmoothingEnabled=true; ctx.imageSmoothingQuality='high';
    const D=deckArt.deck;
    const s=Math.max(W/D.width, ph/D.height);          // cover-fit 進面板
    const dw=D.width*s, dh=D.height*s;
    const dx=(W-dw)/2, dy=y0+(ph-dh)/2;
    if(deckArt.sky){
      const S2=deckArt.sky, sw=S2.width*s, sh=S2.height*s;
      const pan = cam.angle*SKY_PAN + skyDrift;        // ← 見下一節
      const ox=((-pan%sw)+sw)%sw;
      for(let k=-1;k<=Math.ceil(W/sw)+1;k++) ctx.drawImage(S2, dx-ox+k*sw, dy, sw, sh);
    }
    ctx.drawImage(D, dx, dy, dw, dh);
  }
```

⚠⚠ **一定要在 `imageSmoothingEnabled=true` 的區段裡畫**。`resize()` 為了地形的
像素感把整個 ctx 的平滑關掉，天空層縮放時用最近鄰會出現週期性的階梯邊
（同 `drawPanel` 裡舵輪那段註解講的同一個坑）。函式尾巴本來就會關回去。

⚠ 原本那個 `#12101a → #08070d` 的漸層**留著**：cover-fit 在極端比例下左右會露一點邊，
那層漸層就是底。

## 四、怎麼動（Ray 要的「船動時雲海向後跑」）

```js
const SKY_PAN   = 0.6;    // ×W：每弧度捲動幾個畫面寬（航向 → 橫掃）
const SKY_DRIFT = 0.010;  // px/ms per 速度單位（前進 → 持續漂移）
let skyDrift=0;           // loop 裡：skyDrift += spd*SKY_DRIFT*dt;
```
`pan = cam.angle*(SKY_PAN*W) + skyDrift`

- **轉向**綁 `cam.angle`：轉舵，天空橫掃 —— 這是**物理正確**的那一半，
  而且與上半 3D 視窗的航向自動一致（兩邊讀同一個 `cam.angle`，鐵律 7）。
  起始值 `0.6*W` ≈ 轉 90° 掃過約一個畫面寬。
- **前進**綁速度累加：Ray 要的「船動就往後跑」。
  ⚠⚠ **但這一半物理上是假的**：從正前方的視角看，直線前進不會讓雲橫向移動
  （遠方的雲是朝你放大、往兩側掠過）。所以 `SKY_DRIFT` 要**調得很慢**，
  當成「風把雲吹過去」的氛圍，不是速度表。看起來怪就設 0。
- ⚠ `skyDrift` 是**純視覺狀態**，不要進存檔、不要跨場，回到飛行畫面歸零就好。

## 五、成本

面板每幀多 2~3 次 blit。`drawPanel` **現在就已經**每幀貼基座（比畫面還寬）與
舵輪（直徑 606），新增的都比那兩張小；畫面本來就整張重畫，重繪策略不用改。
以 390×844 ＋ DPR 2 估，每幀多約 130 萬裝置像素的純點陣複製 ——
在地形那支逐像素 ray march 旁邊是零頭。

⚠ 唯一要量的是**低階機**：`Q().dpr` 降到 1 時這幾張也跟著小，理論上更省；
但還是照慣例在 q3 上看一次 fps 有沒有掉。

## 七、已接上（ver -1078，程式 session）

接點與這份稿一致，**三處與稿不同**，都寫在 `flight/index.html` 的註解裡：

1. **要裁在面板內**（稿上漏了）：cover-fit 的高一定 ≥ 面板高，不裁的話會蓋到
   3D 視窗下緣。現在兩層畫在 `ctx.rect(0,y0,W,ph)` 的 clip 裡。
2. **前進的漂移綁「實際位移 `mv`」不綁 `cam.speed*dt`**：`mv` 是船真的移動的那一行
   （`cam.x+=fx*mv`），停船／交棒進戰鬥／對話暫停時它本來就是 0，Sturm 與開發用
   加速也自動吃到 —— 不必在這裡再判一次（鐵律 7/8）。
   係數因此改成 `SKY_DRIFT`＝**每 1000 世界單位捲動幾個畫面寬**（現行 `-0.06`，
   負＝往左＝往後）。看起來怪就設 0；方向不對就改正負號，只有這一個常數。
3. **載失敗就放棄不重試**（`im.onerror` 把它記成 null）：圖還沒交的期間，
   每次開機噴一輪 404 是雜訊。圖一放進 `flight/` 就會自己生效，程式不必再動。

順手做的：`primeArt()` 把這兩張也列進預熱（每幀都貼，解碼成本要在載入階段付掉）。

**實測**（用程式生的假圖注入 `deckArt` 驗證，沒有落任何檔案進 repo）：
兩層都畫在面板內、沒有溢出 3D 視窗、在基座與舵輪之後；轉舵時天空橫掃而甲板不動，
方向與上半 3D 視窗一致；推 `skyDrift` 時天空往左走、甲板不動。

⚠ **還沒驗的**：真圖的地平線對不對得上（要兩張都到位才驗得了）、低階機（q3）的 fps。

## 九、前進改成「從消失點往外擴」（ver -1080）

> Ray：「前進的時候背景不應該左右平移吧？應該要往 viewer 方向收，做得到嗎？」

做得到，而且他是對的 —— **第四節那一半的作法是錯的**（稿上自己也寫了「物理上是假的」）：
直線前進的光流是**以正前方為中心的放射狀擴張**（FOE，focus of expansion），不是橫移。
**橫移那一半整個退場**（`SKY_DRIFT`／`skyDrift` 已移除），轉向那一半一個字沒動。

- **FOE ＝ 畫面橫向中心 × 天空層的地平線那一列**（正前方無限遠的那個點）。
  以它為中心放大：**地平線整條不動**（線上每一點到 FOE 的縱向距離都是 0，
  所以任何倍率下都停在原處 —— 這是算式保證的，不是調出來的），其餘往外擴。
- **循環用經典的無限縮放，不是「放到底跳回去」**：同時畫兩層，尺度差一個
  `SKY_ZOOM_F`，小的那層淡入蓋在大的那層上；一個循環走完時小的剛好長到大的
  那層的起始尺度，兩者交棒。
  · 兩層的尺度分別是 `F^u`（≥1）與 `F^(u+1)`（≥F）—— **都必然蓋滿面板**，
    所以大的那層用 α=1 當底，不會透出下面的漸層。
  · 自檢：`u→1` 看到的是 F 倍那一張，`u=0` 看到的也是 F 倍那一張。
- `F` 不要大：它同時決定**最大放大倍率**（F²）與淡接時兩張圖的尺寸差 ——
  太大就會被放糊、而且看得出是同一張圖疊影。現行 **1.6**（最大 2.56 倍；
  天空層本來就被縮到 0.435 倍在畫，所以到頂也只是 1.1 倍放大，不會糊）。

**旋鈕**（只有這兩個）：`SKY_ZOOM_F` 1.6 ／ `SKY_ZOOM_PER` 4500（前進幾個世界單位
走完一個循環；滿速 360 單位/秒 → 約 12 秒一圈）。嫌慢就把 `PER` 調小。

**實測**：逐像素取樣天空那一列，`u=0 / 0.25 / 0.5 / 0.75 / 0.999` 五個相位的雲確實在動，
而 `u=0.999` 與 `u=0` 幾乎逐像素相同（差 1~3 階，來自 α=0.999 與 0 的混合）——
**接縫是看不出來的**。q3 仍是 60 fps。
實測幾何（668×1199 視窗）：`sc`0.435、甲板 668×445、地平線落在面板頂下方 **61px**。

### 九之一、修：往正前方飛還是會橫移（ver -1081）

> Ray：「70 分，我往正前方飛還是有左右橫移」

-1080 把天空層貼在**甲板層的左緣**（`dx`），但天空層有**兩倍寬**（3072 vs 1536），
所以它的基準圖心落在畫面中心**右邊 `dw/2`**。橫向平鋪時那個偏移看不出來（平移一個
貼圖寬長得一樣）—— **可是一旦以消失點為中心放大，偏移就跟著倍率一起長**：

    圖心 ＝ foX + k × (基準圖心 − foX)

基準圖心 ≠ `foX` 的話，`k` 一變圖心就橫著跑。實測一個循環內：

| `k` | 1 | 1.6 | 2.56 |
|---|---|---|---|
| 舊式圖心 | 668 | 868 | 1189 |
| 新式圖心 | **334** | **334** | **334** |

面板才 668 寬，而舊式在一圈之內橫移 **521** —— 那就是他看到的東西。

**修法**：基準位置改成把圖心釘在消失點上（`skyX0 = foX − sw0/2`），於是
`圖心 ≡ foX`，任何倍率下都不動 —— 與「地平線整條不動」同一個道理（算式保證）。
⚠ 自檢：**任何要「以某點為中心縮放」的平鋪圖層，先確認它的基準中心就在那個點上**；
平鋪讓基準偏移在不縮放時完全隱形，所以這個錯只有在加上縮放的那一刻才會現形。
