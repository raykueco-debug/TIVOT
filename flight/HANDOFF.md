## 一、這個模組是什麼

單檔 `flight/index.html`（classic script，非模組），一個 heightmap raycaster：
玩家駕飛空艇在「銀月大陸」上空飛行，下半是舵輪操作盤。

**必須用 http 開**，且改 `settlement.js` 之類的外部檔時要用 `dev_server.py`：

```bash
py dev_server.py 8130
```

> ⚠ `.claude/launch.json` 那幾個 server 用的是 `python -m http.server`，**沒有 cache 標頭**。
> 改完 `settlement.js` 會餵舊檔——我在這一輪被騙過一次（以為 `seaAng` 沒生效）。
> `dev_server.py` 就是為此而生（回應加 `Cache-Control: no-store`）。

## 二、渲染管線的關鍵事實

這些不是選擇，是**量出來的**，改動前要知道：

| 事實 | 數值 | 影響 |
|---|---|---|
| 3D 緩衝解析度 | `BW=234`、`BH=334`（`W*0.60`） | 上採樣約 1.67 倍，世界是低頻的顆粒感 |
| 玩家俯角 | **2°~18°** | 幾乎平視，不是俯視 → 剛體怪只需要**水平一圈**方位圖 |
| 縱向投影 vs 橫向 | `scaleH·syk ≈ 558` 對 `W/2 = 195`，約 **2.9 倍** | 任何「高度」都會被放大 2.9 倍，`planTall` 給大就破圖 |
| 一個地圖像素 | `MAP_SCALE = 20` 世界單位 | 全域地圖解析度太粗，塞不下城市細節 → 城走獨立貼圖 |
| 海平面 | `CLOUD_H = 44` | **低於它就是雲海**。在大陸內部把 HGT 設 0 會打出直通雲海的洞（＝裂谷，不是水） |

**投影的唯一正解**：任何要「貼在世界裡」的東西，都必須走**跟地形完全同一條投影式**
（世界座標 → z → sv → 緩衝列 → 螢幕）。用仿射矩陣近似會失敗，因為投影是 1/z 的非線性。

## 三、目前的東西

### 聚落（27 座）
- 資料在 `SETTLEMENTS`；生成器 `settlement.js`（純函式）。
- 地形處理（`loadWorld` 內，順序不可換）：
  1. **鏟平**城下地形（city 級整平到 2.6R、裙帶到 3.6R）→ 算出 `S.gh`
  2. **地形遷就插畫**（有 `plan` 的城）→ 依插畫水域挖水面／補陸
- 臨海聚落**必須給 `sea`**（向海方位，弧度）：棧橋固定生在區域 +x，不給就指向內陸。

### 手繪平面圖的城（目前只有薇拉馮德港）
- `flight/build_city.py` 由等角視插畫產出 `*_plan.webp` + `*_h.webp`（高度圖）。
- 渲染走**網格投影**：切成 N×N 格，每格各自投影，畫進 0.6 倍緩衝再 nearest 放大。
- **置放的標準流程**（沿用到其他城）：拿插畫自己的**水域遮罩**（藍色像素）去對真實海域，
  掃描城心與旋轉、取吻合度最高者。薇拉馮德港＝`(1366, 936, 1.40)` → 91.7%。
- ⚠ `mx/my/planW/planRot` 在 `index.html` 與 `build_city.py` **兩邊都有**，必須一致。

### 敵人（3 種）
共用行為：視野外刷新 → 橫向巡航 → 距離縮到 `d0` 的 60% 轉追擊 → 進 210 單位遭遇提示
→ 3 秒消失重新計時。速度、轉速、體型參數在 `ENEMY_KINDS`。

| 名稱 | plan | 素材 | 備註 |
|---|---|---|---|
| 巨型蜈蚣 | chain | 俯視圖逐節取樣 | 左右扭 |
| 羽蛇 | chain | 同上 | **上下**扭、鳥翼慢揮（平滑正弦，不用 `\|cos\|`）|
| 空賊 | rigid | 4 方位圖 + 交叉淡入 | 依朝向換視角 |

素材切分：`flight/split_enemy.py`（六視圖合成稿 → 單視角 webp，全張共用一個縮放係數）。

### 其他
飛鳥群、橫條羅盤帶（船與面板之間）、逐欄深度遮擋、滿版地圖。

## 四、踩過的坑（最有價值的部分）

1. **夾制過的深度不能拿來畫。** `project` 對 `z<24` 夾制以避免除零，但夾過的角會被推到
   完全錯的螢幕位置，那一格就整片扯開。要用**未夾的**深度判斷該不該畫（`z<60` 就跳過）。

2. **「等 v 線不是等深度線」。** 把貼圖切成**橫條**去投影，只有在條與視線垂直時才成立。
   平面圖轉過角度後，同一條的兩端深度差到 1658 vs 544 —— 必須切成**二維網格**。

3. **逐格判斷會抖。** 「格心落在海上就不畫」這種逐格剔除，格子大小隨距離變，
   鏡頭一動整塊整塊跳 → 海岸線鋸齒抖動。靜態的東西要**烘進素材**。

4. **剔除半徑要含實際畫出來的範圍。** 用城區半徑當剔除半徑，但手繪圖比它大 → 又變成
   「城心進畫面才整張冒出來」。這個 bug 在這一輪出現過**兩次**。

5. **貼圖的「細節密度」和「像素大小」是兩回事。** 城即使像素大小與地形一致，
   來源解析度太高仍會讀起來比地形精細。要降來源解析度（768 → 440）。

6. **顏色分類要用色相不要用亮度。** 城市插畫的街道是淺色、屋頂是深色，
   照亮度分會把街道當低地、屋頂當高地。

7. **`ctx.filter` 在部分 Safari 沒有。** 固定的色調對齊要**烘進素材**，不要 runtime 做。

8. **`source-atop` 不是 `multiply`。** 要對離屏緩衝上色又不弄髒透明區，用 `source-atop`；
   Canvas 的 `multiply` 走 source-over 合成，會把整張填成實心色。

9. **UI 不要進低解析緩衝。** 提示文字跟著糊就成了糊掉的字，不是像素風。

10. **測試腳本會騙人。** `update()` 每幀把油門衰減回 0，只在迴圈外設一次 `cam.speed`
    等於玩家停在原地 —— 我因此誤判「玩家追不上怪」。

### 已知的設計前提
日夜**不會即時推移**，而是戰後結算時跳一段 —— 實際只會停在**夜／黎明／早／黃昏**四個狀態。
現有的連續光照曲線在那四點取值都對得起來，不必改成離散表；實作結算時直接指定
`clock.minutes` 到那四個值即可。
