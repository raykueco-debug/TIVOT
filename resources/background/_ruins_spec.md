# 古代遺跡 Ruins — 場景規格（Ray 交辦）

19 個場景、**20 張圖**（入口在戶外，做日／夜兩張；其餘全是室內，各一張）。

## 共用規格

- 橫式 3:2、平視圖、**中央留空給人物立繪（景物擺兩側）**。
- 日式動漫 clean lineart、cel shading、**絕不要顆粒雜訊噪點、不要油畫質感**、無文字無浮水印。
- **建築全石質**：巨大切石砌塊、石柱、石拱、石階；風化、裂縫、苔蘚與藤蔓爬進來。
  **沒有木造、沒有金屬建材。**
- **森林風**：遺跡被森林吞沒 —— 樹根穿透石縫、落葉、崩塌處有光從上方漏下、空氣裡有塵埃光束。
- ⚠ **連續感與過道感**：這些是同一座遺跡裡相連的房間 ——
  **石塊尺寸、砌法、紋樣、苔蘚顏色必須一致**；每張畫面都要看得到
  **通往下一個房間的門洞、拱道或階梯**。
- ⚠ **但每一格要認得出來**：每個場景有一個明確的辨識物（見下表）。
- 室內光源只有三種：崩塌處漏下的天光、石縫裡的發光苔、幾盞長明火。
- **畫面上不要人。**

## ⚠ Gemini 抓圖的兩個坑（2026-09-02 實測）

1. **`下載原尺寸圖片` 這顆鈕要先 `scrollIntoView` 才給全解析。**
   捲不到位就按（含 JS `.click()`），會靜靜拿到**剛好一半**的那一份
   （2528×1696 → 1264×848）。`Ruins_Spring` 就是這樣來的。
   作法：`b.scrollIntoView({block:'center'})` → 等 1.2~1.5 秒 → `b.click()`。

2. **Chrome 會擋掉「連續自動下載」，而且一點提示都沒有。**
   症狀：按鈕照按、JS 回傳正常、`~/Downloads` 就是不出現新檔，
   **連之前抓成功過的舊圖也抓不到** —— 那是判斷它是瀏覽器層而不是 Gemini 層的關鍵。
   解法：**重載那一頁**（`navigate` 同一個 URL），重載後**只保證下得了一張**，
   下一張再重載一次。（重載不會掉對話，Gemini 的紀錄在伺服器端。）
   ⚠ 重載之後 Gemini 只會 lazy-load **最新的 10~11 張**，按鈕的 index 會整個位移 ——
   不要沿用上一輪的 index，要**用圖的長寬比重新認**（例：Vault 是 1024×559，
   其餘都是 1024×687）。

3. **視窗比截圖寬時，右上角那排鈕點不到。**
   本輪可視只有 ~1132 CSS px、版面卻是 1706 —— 下載鈕落在畫面外。
   `document.documentElement.style.zoom='0.6'` 可以把它拉進來，
   但**最穩的還是走 JS `.click()`**（配上第 1 條的 scrollIntoView），不必算座標。
