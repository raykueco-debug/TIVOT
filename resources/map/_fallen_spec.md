## 一、拓樸：5 格・4 邊・**環數 0**（樹狀）

```
                 祭壇
                  │
   沉水石坑 ──── 傾石岔口        ← 唯一的岔口（三向）
                  │
                斷柱道
                  │
                崩塌門廊
                  │
               原野（跨圖）
```

| 節點 id | 中文 | 向數 | 出口 |
|---|---|---|---|
| `entry` | 崩塌門廊 | 2 | `up:'causeway'` ＋ 跨圖出口（後） |
| `causeway` | 斷柱道 | 2 | `{ up:'fork', back }` |
| `fork` | 傾石岔口 | **3** | `{ up:'altar', left:'basin', back }` |
| `basin` | 沉水石坑 | 端末 | `back` |
| `altar` | 祭壇 | 端末 | `back` |

- **一直按↑**：崩塌門廊 → 斷柱道 → 傾石岔口 → 祭壇（走到底就停，沒有同向繞圈）。
- ⚠ 過道與端末寫成 `{ up:<前進>, back:<退回> }`，**不要寫死 `down`**（憲法 §6.5.4 ver -903）——
  `back` 由 `exitsOf` 現算成來時方向的反向，這張圖之後接到別張時才不會被綁死成垂直主軸。
- ⚠ **入口那一格不可以有戰鬥**（§6.5.2）：`entry` 留空。
- ⚠ **結算怪**：只有一個跨圖出口＝末端型，ver -895「擺在沒走進來的那個出口」不適用，
  由資料指定即可（建議 `altar`）。
- ⚠ 迷霧預設是有的（ver -913），**不要**寫 `mist:0`。

## 二、畫風鐵則

### 1．坍倒石製 ＝ 只有素面的石頭

| ✅ 要 | ⛔ 不要 |
|---|---|
| 粗鑿的灰色巨石塊（石灰岩／花崗岩） | 金飾、鍍金、彩繪玻璃、壁畫、雕像 |
| 倒下的**圓柱鼓**、斷裂的過梁、風化的表面 | 任何精緻的雕飾或花紋 |
| 石縫裡的野草、苔、低矮灌木、被風吹歪的樹 | 文字銘刻（祭壇的幾何刻紋除外） |
| 碎石與裸土 | 東方元素（朱漆・斗拱・飛簷・琉璃瓦・龍鳳雲紋・燈籠） |

⚠⚠ **要與地宮（`Undercity_*`）明顯分開**：那邊是**被埋掉的華麗皇宮**（大理石、鍍金、
吊燈、彩色石片地板），這邊是**素面石頭、在戶外、被草長回去**。
兩者都叫「遺跡」，但如果這一組畫得太精緻，玩家會讀成同一個地方。

### 2．⚠⚠⚠ 全場景露天（Ray 指定）

**五張都要看得到天空**，沒有屋頂、沒有洞窟、沒有室內。
⇒ 連帶：**五格全部都有室外光，照「有室外光才有差分」那條，五格都要四時段差分**
（＝20 張）。**已全數產出入庫**（見 §四）。

### 3．遼闊七招照舊
鏡頭壓低／地平線在下三分之一／近端用倒石或斷柱框住畫面／重複元素等距縮小／
深處放人影或缺口當尺度／光源放遠／不要塞滿。

## 三、逐格特徵

| 格 | 向數 | 這一格長什麼樣 |
|---|---|---|
| **崩塌門廊** | 入口 | 一道還立著的巨大石門框：兩根方形巨柱撐著一條**歪斜裂開的過梁**；兩側牆倒成碎石坡；**穿過門框看得到裡面的路**往深處去 |
| **斷柱道** | 通道 | 兩側各一排倒下的圓柱，斷成一節節的**圓柱鼓**像骨節排開；幾根只剩半截仍立著；中間一條筆直的土路往深處收斂 |
| **傾石岔口** | **三向** | 三塊**巨大的斜倚石板**互撐出一塊三角空地；⚠ 三個方向各一條**真的走得進去的路**（正前上坡／左邊下坡／畫面下緣是來路），開口大小相近、地面土路連續延伸進去 |
| **沉水石坑** | 端末 | 鋪石廣場**塌陷成淺坑**，坑底一窪水映著天；四周是崩落的階梯與傾斜鋪石；蘆葦與半泡在水裡的落石。四面被石牆與土坡圍死 |
| **祭壇** | 端末 | 路的盡頭：**粗鑿的整塊石台**，台面刻著**幾何刻紋**（同心圓／直線／三角，不是文字）；外圍一圈**未經雕琢的立石**（menhir），有的倒了；更外圈只剩一排**圓形柱基**；野草沿石縫長成一圈 |

## 五、⚠⚠⚠ 這一組的產法改了：**畫法直接寫進生成提示詞，不走 Gemini 後製**

§5 的分工是「GPT 出內容 → Gemini 做平塗去顆粒＋時段差分」。**這一組走不通**，
改成 **GPT 一次跑完 5 景 × 4 時段 = 20 張**，把 cel shading 那一段
（平塗色塊＋硬邊陰影、2~3 階、明確深色描邊、石面整塊平面、⛔ 不要質感貼圖、
草木成團塊狀、雲是有形狀的塊、絕不要顆粒感）**逐張寫進生成提示詞的結尾**。

### 為什麼推翻 Gemini 那一趟（實測，Ray 兩次回報）

⚠⚠⚠ **Gemini 做不到「只改畫法、不動內容」** —— 提示詞寫死不准動也沒用：

| 場景 | 它擅自做了什麼 | Ray 的話 |
|---|---|---|
| night（任何一景） | **把天上的星星連成星座線** | 「gem 那個天才把天上的星星連出星座線了」 |
| Causeway | 遠景的人影不見了 | —— |
| **Fork** | **整張重畫**：白天變成黃昏，還加了一堆營火 | 「gem 那個混帳在圖裡加料」 |
| **Basin** | 淺水坑變成一口深井，井邊多一個人 | 同上 |
| Basin（加了禁止清單之後重測） | **還是多了兩座石拱** | —— |

⇒ **結論：「嚴格按原圖畫」這條指令 Gemini 不遵守，加禁止清單也不遵守。**
內容一旦被動過，四個時段就不是同一個地點的差分了 —— 那比殘留一點顆粒嚴重得多。

### 這一輪的成本與效果

- 慢（每張約 1.5~2 分鐘，20 張約 40 分鐘），但**一次跑完、零逾時**（20/20 ok）。
- ⚠ night 那一則要明寫 **「絕對不要把星星連成線、不要星座線、不要星座圖、不要銀河帶」**
  —— 那是 Gemini 犯過的錯，GPT 也會犯。
- **顆粒量測**（憲法 §5 的平坦區高頻，校準點＝**舊版那五張**，Ray 說「都有顆粒感」）：

| 格 | 舊版（無時段） | 新版 day | 新版最高（四時段） |
|---|---|---|---|
| Altar | 1.42 | **1.33** | 1.33 |
| Basin | 1.56 | **1.22** | 1.44 (dusk) |
| Causeway | 0.88 | **0.66** | 0.73 (dusk) |
| Entry | 0.99 | **0.81** | 0.81 (day) |
| Fork | 1.74 | **1.12** | 1.12 (day) |

  **五格全數下降**，night 那一欄一律 0.45~0.77（最乾淨）。
  ⚠ 照憲法仍以 100% 裁切肉眼複核為準 —— 並排看：石面由密集斑點變成整塊平面、
  草木收成有描邊的團塊、水面變成平塗色塊。

### ⚠ Ray 對「縮小之後誰比較好看」的判斷

Ray：「糊的應該比較好，因為遊戲畫面不會放到那麼大，縮小以後效果好、
gpt 的細節縮小以後反而扎眼」→ 實測**在遊戲的實際顯示尺寸下兩者差很少**
（DPR2 高頻 0.321 vs 0.373、DPR1 1.041 vs 1.039），而且背景在 DPR2 上
是以 **≈0.92 倍**顯示的（幾乎原尺寸）—— 所以「縮小以後會扎眼」在這裡不成立。
真正的差別是**內容有沒有被改掉**，那才是選 GPT 的理由。

## 六、⚠ 這一組踩到的坑

### 1．第一串卡死

第一次送出後**五分鐘沒出圖**，停止鈕一直在、`[data-message-author-role=assistant]`
也建起來了，但圖始終沒有。那一串的網址是 `chatgpt.com/c/**WEB:**7fc86cdc-…`
—— 多了 `WEB:` 前綴，對話八成沒在伺服器端正常建立。
⇒ 照憲法「**生圖卡住立刻換串**」處理：中止、開新串、同一組提示詞重送，
**五張一次全過**（每張約 40 秒）。⚠ 不要在原串等或重送。

### 2．⚠⚠⚠ 「卡住」有一半是我自己沒送出

Ray：「**是你沒送出 prompt，卡的是你不是 gem**」——
我把「night 卡住」報成 Gemini 的問題，實際上提示詞還躺在輸入框裡（`boxLen: 212`）。
我原本的送出判準是「數對話則數有沒有增加」，而一則重複的 dusk 把它灌水了。
**正解：送出判準一律是「輸入框清空」，而且要重試：**

```js
window.__go=async(txt)=>{ for(let a=0;a<4;a++){ window.__fill(txt); … window.__hit(btn);
  for(let i=0;i<25;i++){ await sleep(1000);
    if(window.__box().innerText.trim().length===0) return {sent:true,a}; } } }
```

修好之後 night 第一次就出圖。

### 3．下載會漏，但圖跑不掉

20 張裡有 1 張（`Basin_dusk`）下載沒落地。照憲法「下載卡了放著」——
隊列跑完之後用 `window.__dl(索引,'檔名')` 單獨補抓一次就好
（`__nimg()` 的索引與隊列順序一一對應）。
