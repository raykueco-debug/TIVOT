# 槍棺地圖（手繪羊皮紙）— 場景規格

## ⚠⚠⚠ 先排小地圖，再畫場景（2026-09-07，Ray 定案，全美術產線適用）

> Ray：「以後繪圖應該**先排小地圖再下去畫**，才不會畫出來移動邏輯不通」

**一張新地圖的順序是：拓樸 → 每一格要幾個出口 → 場景圖 → 小地圖。**
不是「先畫一批好看的場景，再想辦法把它們連起來」。

**為什麼**（木雅克神殿就是反例，繞了十幾版）：場景圖畫死了那一格**能有幾個出口** ——
畫面上看得到幾道門，那一格就只能接幾條路（§`_ruins_spec.md`「三個出口要真的是路」）。
先畫的 18 張裡**只有 3 張畫得出側向通道**，於是：

- 地圖只做得出「一條主軸＋一個岔口」，Ray 連退三版（「太過一直線」「根本一直線」）；
- 為了補救得**回頭加畫三張三岔**（Crossway／Brazier／Hollow，一層一張）才長出抉擇點；
- 中途每改一次拓樸，小地圖就得整張重畫（**地圖的每一筆線都是拓樸的函數**）。

**所以開一張新地圖時，第一件事是問**：
1. 這張圖要幾格？主軸多長？要幾個**抉擇點**（3~4 向）、幾個**末端**？
2. 逐格列出**它需要幾個出口、分別朝哪個方向** —— 這是**場景圖的規格**，
   不是畫完再看著辦。
3. 抉擇點那幾格的提示詞要明寫「正面一道＋左右各一道**真通道**」
   （門框／塌開的缺口、地面延續進去、裡面暗下去）。
4. 拓樸**定案並接進 `script/town.js`、實走過**，才畫小地圖。

- ⚠⚠ **拓樸是遊戲設計，不是美術** —— 定案前不要開始畫小地圖。
  神殿那幾版就是拓樸還在動的時候畫的，全部白畫。
- ⚠⚠ **小地圖上的相對位置＝遊戲裡的箭頭方向**（ver -908 程式端確認）：
  某格畫在另一格的左邊，玩家就是按左過去。所以構圖可以疏密不均、線可以彎，
  但**上下左右的相對關係一格都不准挪** —— 挪了地圖就在騙人。
- ⚠ 這條與「同一條邊的兩端必須是相反方向」（CLAUDE.md §6.5.4.3 後）是同一件事的
  兩端：那條管資料，這條管圖。


點開槍棺右下角的書 → 控制面盤變成這張圖，所在地閃爍光點。
程式端只讀 `img` 與 `spots`（比例座標），所以**圖上每個地點的位置就是規格**。

## 共用規格（ver -883，Ray 定案）

- 橫式 **1536×1024**，舊羊皮紙、褐墨、撕裂毛邊。
- **畫風＝鋼筆簡筆素描**（Ray 指定）：單色褐墨線稿、**不要上色、不要塗滿、不要水彩**。

### ⚠⚠⚠ 「多簡」的判準：那是主角一邊走一邊畫的（2026-09-07，Ray 第三次退件後定）

> Ray：「地圖沒有遵守原則，上面的圖都是鋼筆簡筆畫，**主角邊走邊畫出來的**，
>   不會那麼細緻，**極簡**」

**這一節取代原本那句「每格的小插畫是幾筆帶過的速寫」** —— 那句話擋不住模型的預設畫法，
**連退三版**（v2「太細膩」、-908 版「太細緻」、-909 版同樣太細緻）。

**設定就是判準**：他手上只有一支筆、站在黑暗的通道裡、沒有時間。所以每一格是
**三到八筆的記號**，不是一幅小插畫。具體到「改畫什麼」（§5：說「不要細緻」沒有用）：

- 每格 **3~8 筆線**就結束。例：巨像＝一個坐姿剪影＋一條底線；火盆＝一個碗＋三道火苗；
  斷橋＝兩段橋板＋一道斷口；裂隙＝一道之字形。
- **不要排線、不要交叉影線、不要點描、不要陰影。**
- **不要畫材質** —— 石縫、磚紋、苔、藤蔓、羽毛狀樹葉一律不畫。
- **不要畫出體積或景深**，全部是**同一個線寬的輪廓線**；不要畫成銅版畫／蝕刻版畫。
- ⚠⚠ **提示詞裡要逐格寫出「畫什麼、幾筆」**，不要只寫「極簡」。
- **交件自檢**：把成品**縮到四分之一**，每一格還讀得出是什麼＝過關；
  要瞇眼才看得出來＝畫太多了。另一個問法：**隨便挑一格放大，數得出幾筆嗎？**

⚠⚠⚠ **根因是「畫風基準圖」在跟指令打架**（-909 之後才想通）：
前三版我都拿 `map_shinierforest.webp` 當畫風錨 —— **但那張本身就很細**
（山有排線、遺跡有陰影），等於一邊叫模型簡化、一邊給它一張精細的範本看。
**正解：材料與畫法要分開餵。**
- 只裁**沒有插畫的部分**當材料參考（紙色、皺褶、撕邊、墨線的串珠感、圓墨點、草書字體）
  —— 現行的 `scratchpad/ref_material.jpg` 就是從森林那張裁「一段線＋一個地名」＋
  「一塊空白紙與撕邊」拼出來的。
- **小圖的畫法完全用文字規定**（上面那張逐格清單），不給它任何插畫看。
- 實測：這樣做方向就對了，但**還要再收一階**。第一版仍有四格超標，
  全部是同一類毛病 —— **模型會把「結構」畫成「材質」**：
  · 三個拱門（Collapsed／CorridorB／Entrance）**逐塊描拱石**（磚縫）
  · 齒輪畫成雙層輪圈 ＋ **十根輻條**
  改法是把那幾格再寫死一次：「拱門＝**一條 ㄇ 形弧線＋兩條腳**，拱圈上不要任何
  分隔線」「齒輪＝**一個圓＋三根輻條＋一根連桿**，不要第二圈、不要齒」。
  ⚠ **要附上「逐格裁出來排在一起」的審圖**（`icon_audit.jpg` 那種）並明寫
  「其餘 18 格照抄」—— 只講要改的那幾格，模型才不會順手把別格也重畫。
- ⚠⚠ **再簡化那一輪會掉東西**：第二版把四格改對了，但**掉了幾顆節點墨點**
  （Brazier／Entrance 完全沒有）。**那不要重生成** —— 墨點是幾何不是繪畫，
  自己補（統一半徑、取樣既有墨色、`darken` 合成）比再擲一次可靠得多。
  ⇒ 通則：**形狀交給人／幾何交給程式，畫法交給模型。**
  · 程式端的同族教訓是 ver -417 的槍棺齒輪：解了三版幾何最佳化（內接圓、避釘惰輪），
    每一版都更「正確」也更醜，最後 Ray 直接在貼圖上標了位置與大小
    （CLAUDE.md §6.10「UI 元件的位置與大小是設計問題，不是最佳化問題」）。
  · 三者的分野：**構圖與美感 → 人決定**；**座標、圓點、連線、對齊 → 程式算**；
    **筆觸、質感、上色 → 模型畫**。拿其中一個去做另一個的事，就會繞遠路。
- ⚠⚠ **去白背走 alpha 通道**（Ray 每次都提）：撕邊之外一律透明，不要留白框、
  不要白霧邊 —— 遊戲裡它是疊在場景上的。
- ⚠⚠⚠ **圖上只准有英文節點名，而且是極草書**（Ray：「圖上的字只能是各節點的英文
  極草書，之後地名留給 code 壓字，這樣以後才能翻譯」）：
  · 那串草書是**裝飾**，不必讀得清楚 —— 真正給玩家看的地名由程式壓在上面。
  · **一個中文字都不要**、不要標題、不要圖例、不要方位、不要比例尺、不要年份。
  · 字烘進圖裡就翻不了譯（日文／英文版要換字），所以可讀的那一層一定要留給 code。
- 每個地點：一個**墨點**（程式的光點會蓋在這裡）＋ 那一格的辨識物速寫 ＋ 草書英文名。
- 地點之間用**手繪墨線**連起來；換層用**虛線**。
- 基準：`map_shinierforest.webp`（夏爾森林那張，已驗收）。

## ⚠⚠ 路線圖必須畫出「分岔」與「末端」（ver -882，Ray 退件時指出）

> Ray：「這張不行」「地圖太過一直線了，要有分叉跟迷宮感」
> 「要把端點跟過道分清楚，適合當端點的圖就不要再衍生其他路，分岔過道就讓他路線多擇」

**`map_shinier_ruins.webp`（第一版）被退回的原因**：三層各畫成**一排直線**，
每個地點只接左右兩邊 —— 看起來像三份清單，不是地圖。玩家看不出哪裡要選路。

**重畫時的硬規則：**

1. **連線要照下面那張拓樸表**，不要自己排成一排。
2. **末端（dead end）只准接一條線** —— 畫面上要看得出「那條路到底了」。
3. **樞紐要接三～四條線**，而且方向要散開（不是左右一直線）。
4. **環路要看得出是環**（走一圈回到原點），不要畫成兩條平行線。
5. 位置可以為了構圖挪，但**連線關係一個都不能改**。

- **背景**走 `bandNames` 組出來的候選鏈，快取由 `config.js` 的 **`ASSET_VER`** 管

### ⚠⚠⚠ 同名覆蓋一張**已經上線**的地圖：兩件事，一件都不能少

（2026-09-07 踩到：程式端把第四版掛上去跑了，我隨後覆蓋成第五版卻沒有立刻報。）

1. **立刻報版本** —— 一句話：「`map_ruins_shinier` 覆蓋了，第五版」。
   程式端要把資料裡的 `?v=4` 改成 `?v=5`。不報的話所有人（含我們自己的瀏覽器）
   抱著舊快取，而**畫面上完全看不出來** —— 圖還在，只是舊的。
   ⚠ 這與娜塔莉 `dead` 立繪那個查了四版的坑是同一個（CLAUDE.md §5）。
2. **`spots` 整份重量重給，不准說「只有幾格變了、其餘沿用」。**
   ⚠⚠ 那是錯的直覺：**整張重新生成的圖，連沒改到的那幾格墨點也不會落在同一個
   像素上**。實測第四→第五版，我只要求改四格，**21 格全部都動了**（程式端逐格對過）：
   最大 `catacomb` 0.535→0.463（**74px**）、`darkbridge` 0.120→0.183（63px）、
   `well` 0.371→0.392、`crossway` 0.613→0.576。在 1536 寬上就是光點整個偏出墨點。
   ⇒ **只要是整張重新生成，就是整份重量**，沒有例外。

### ⚠⚠ 城鎮小地圖（帝都／夏爾村／北方泊地，2026-09-07 交件，三張都一次過）

- **路口與地點要分得出來**：街區那幾格是**路口**，**不畫任何地標**，只有墨點與街道
  交會；**末端才畫辨識物**。玩家一眼看得出哪裡進得去。
  · 例外是中心廣場那一格：可以給**廣場本身**的小記號（帝都圓環＋柱／北泊繫纜柱／
    夏爾村晾獸皮的木架）—— 那是那一格的樣子不是店，而且讓三個中心點一眼認得出來。
- **出航／離開地圖不是節點**：在那一格下緣畫**一小段斷開的路**（港口再加個小錨）就好，
  **不要給它墨點、也不要寫名字** —— 有名字程式會把它當節點而找不到。
- **跨圖出口照畫、但要從 `spots` 濾掉**（夏爾村的 `Forest`、神殿的 `entrance`）：
  圖上留一顆低調的墨點告訴玩家那條路通得出去，但它是**另一張圖**的格子。
- ⚠⚠⚠ **`spots` 的 key 必須是節點 id，不是圖上的草書名**（這次踩到兩處）：
  夏爾村的草書寫 `Wilds`、節點 id 是 **`wild`**；北泊的草書寫 `Square`、
  節點 id 是 **`entrance`**（碼頭大道）。**工單若把兩者寫在同一欄就會弄錯** ——
  交件前拿 `script/town.js` 的 id 對一次。
- ⚠⚠ **不必為中文地名留白**（推翻早先那句「墨點右下方要留得下那一串」）：
  引擎把中文**置中壓在墨點正下方**，而且會自己加紙色暈罩住底下的草書。
  Ray 的規約本來就是「草書是裝飾、可讀的那層留給 code」——**壓過去是對的**。
- **大城 `mist:0` ＝ 一進去就全開**，沒有迷霧幫忙遮，所以墨點、地名、線三者
  不可以互相壓到。

### ⚠⚠ 一串對話連著畫，明寫「同一本地圖集的下一頁」

三張城鎮圖在**同一串**對話裡連著產，第二、三張只寫「畫風、紙、撕邊、墨線、字體、
簡化程度**全部照前一張**，只換內容」—— 紙質與字體自動一致，**比每張重新描述可靠**。

⇒ 通則是**一次只換一個變因**：這裡是「畫風固定、只換內容」；程式端查「圖沒換」
那類 bug 時是「內容固定、只換版本號」。兩者都是讓「不一樣的地方」只剩一處。

### 兩道驗證是分開的，各留各的

| 誰驗 | 驗什麼 | 抓得到什麼 |
|---|---|---|
| 美術（`tools/map_check.py`） | **線有沒有接上**（連通元件） | 某一格在圖上連不到任何地方 |
| 程式端（接 `spots` 時） | **出口方向 ＝ 兩顆墨點的相對位置** | 地圖與畫面上的箭頭互相矛盾 |

⚠ 兩者**不重疊**：線接上了、方向仍可能是反的；方向對了、線仍可能斷。都要跑。

### ⚠⚠⚠ 交件前跑 `mapcheck.py`（連線驗證器，2026-09-07 立）

肉眼逐條看 21 條線**已經漏掉一次**（-908 版的 `Collapsed—Mural` 整段沒接上，
我看過還說「全對」）。所以現在有一支檢查器（`tools/map_check.py`）：抓 22 顆墨點、對照佈局圖的預期格點配對，再用**連通元件**
判斷每一條邊有沒有真的接上，最後印出 `spots` 的比例座標與一張疊圖。

寫它時踩到的三個坑，重寫時不要再踩：
1. **不要「沿著兩點連線取樣看有沒有墨」** —— 取樣窗只要放到 ±11px 就會把
   **地名的墨**算進去，於是「線斷了、但字剛好落在缺口上」會被判成 100% 有墨。
   要問的是**連通性**，不是「這條路徑上有沒有墨」。
2. **判連通之前要先輕微膨脹**（`MaxFilter(5)`）：墨點與線之間常有 **1~2px 的
   抗鋸齒縫**，肉眼完全看不出，但不封起來的話**每一個節點都會自成一塊**
   （實測第一版就是這樣，21 條全報斷線）。真正的斷線是 40~100px，膨脹 2px 封不到。
3. **墨點偵測用侵蝕**（`MinFilter(5)`）：實心圓點侵蝕 2px 還在，細線與文字筆畫會消失。
   ⚠ 它仍會被**圖示裡的實心暗塊**騙到（洞窟口、齒輪軸），所以疊圖**一定要肉眼看過**
   22 個圈有沒有套在正確的墨點上，套錯的手動改。

⚠⚠ **它是「挑出可疑的」不是「判對錯」**：實測 v4 報了 10 條可疑，放大看只有
**1 條是真的斷線**，其餘 9 條是誤判（地名壓在線上、圖示暗塊）。
**數字挑候選、眼睛下判斷**（同 `_ruins_spec.md` 的顆粒自檢）。

⚠⚠⚠ **膨脹量要跟著那一版的線粗細校準，不要固定**（極簡版的教訓）：
極簡版的線比較細、而且**手繪本身就帶小斷點**，`MaxFilter(5)`（2px）之下
報了 7 條斷線 —— 放大看**七條全是連續的**。正確作法是**掃一遍膨脹量看拐點**：

    MaxFilter( 5)  斷 7 條，節點分 8 群
    MaxFilter( 7)  斷 3 條，分 4 群
    MaxFilter( 9)  斷 0 條，**全部連成一群**   ← 拐點

**拐點在 9 ＝ 全圖最大缺口 ≤8px ＝ 手繪斷點**，不是斷線；而真正的斷線是
**40~100px**（v4 那條是 99px），任何合理的膨脹量都封不到。
⇒ **判準不是「某個固定門檻下有沒有斷」，是「要多大的膨脹才會全部連通」**：
掃到 9 以內就收斂＝乾淨；要 20 以上才收斂＝那裡真的斷了。

⚠ **偵測墨點會被撕邊的污漬騙**（實測 50 個候選裡一半在紙緣）。節點座標與其
讓它猜，不如**人工讀一次**（把圖裁出來、疊上 20px 座標格就讀得準），
之後連通判斷與 `spots` 都用那一份 —— 這也讓結果可重現。

### ⚠⚠ 交件前的自檢：逐條核對連線與方位（2026-09-07 立）

小地圖的錯**不會有任何錯誤訊息**，玩家只會發現「箭頭跟地圖對不上」。所以交件前要：

1. **逐條數連線**：節點數、邊數（樹狀就是 `邊＝節點−1`）、每個末端**只准接一條**、
   每個抉擇點的度數對不對。
2. **逐格核對相對方位**：A 在 B 的左邊／上面，要與 `_layout_*.png` 一致 ——
   那就是遊戲裡的按鍵方向。
3. **放大看每一顆墨點**：AI 會多畫「沒有接線的孤兒點」與「沒有名字的轉角點」。
   判準是**一個名字一顆點、一顆點至少一條線**。
   ⚠ 縮圖看不出來，要 2~3 倍裁切逐區看（同 `_ruins_spec.md` 的顆粒自檢）。
4. **數地名**：22 個要到齊、拼字要對、**一個中文字都不能有**。
