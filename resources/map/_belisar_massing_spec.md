# 貝利薩爾遺址 — 3D 量體的素材需求（ver -1164 之後）

> Ray：「3d 模型要盡量接近外廓」→「這是 minecraft 嗎？太方了」→「還是太方，
>   有沒有什麼方法讓它更接近外廓」→ ver -1164 修了四件（色票／山牆／雉堞／收分＋
>   層層退縮），**剩下最後一段差距要靠素材補**。

**要的東西一句話**：一張**正俯視的高度圖**（灰階＝高度），外加一張**正立面剪影**校準。

⚠⚠⚠ **這兩張不是插畫，是技術圖** —— §5 那四條畫風鐵則（anime／cel shading／
clean lineart／不要顆粒）**在這裡不適用，也不要套**。要的是**精確的形狀與精確的灰階**，
不要光影、不要材質、不要描邊、不要透視。

---

## 一、為什麼是這兩張（能解決什麼、不能解決什麼）

現在的量體是**我照著 `Belisar_Exterior_day.webp` 用眼睛排出來的**，而那是一張
**仰角透視**的插畫 —— 從它身上量不出平面位置，只能估。三版下來剩下的差距正是
估出來的那一半：平面太方正、太對稱，外廓圖上那種「順著崖脊歪斜地攤開」排不出來。

| 這一張能解決 | 這一張**不能**解決（仍由程式端產生） |
|---|---|
| 每一塊的**平面形狀與位置**（崖階怎麼歪、翼怎麼伸出去） | 屋頂的**坡**（山牆、錐頂）—— 高度圖一格只有一個高度 |
| 每一座塔的**位置與粗細** | 雉堞、女兒牆 |
| 各部位的**相對高度** | 門窗開口 |
| 整體的**不對稱** | 材質與顏色 |

所以交件之後我不是「換一張圖」，是**把量體的骨架換成量出來的**，屋頂與細節照舊
由 `k:'gable'` / `cap` / `crenel` 這三個原語長出來（ver -1164 已經做好）。

## 二、交件 A（**主要**）：正俯視高度圖

**檔名**　`flight/Reference/belisar_plan_h.png`
（⚠ 交件放 `flight/Reference/`，**不要**用底線開頭 —— 那個前綴在 `.gitignore` 裡）
**底圖**　`flight/Reference/belisar_plan_h_draft.png` ← **直接在這一張上面改**

底圖是我把**現有的量體**反算出來的（`python3 tools/ruin_heightmap.py belisar`）。
在它上面改，座標系、比例、灰階對應全部天生就對，不必自己建。

### 規格（**一個字都不要改**）

| 項 | 值 |
|---|---|
| 尺寸 | **979 × 1166 px**（與底圖同尺寸，不要縮放、不要裁切、不要加邊） |
| 色彩 | **8-bit 灰階 PNG**，無 alpha |
| 比例尺 | **3 px ＝ 1 個世界單位**（整張圖＝ 326 × 389 個世界單位） |
| 灰階 | **線性**：`0 = 地面`、`255 = 320 個世界單位高` ⇒ 高度 = 灰階 ÷ 255 × 320 |
| 視角 | **正俯視**（orthographic top-down）。⚠ 不是等角、不是斜俯視、**沒有透視** |
| 方位 | 圖的**右**＝城堡正面朝的方向（大門開在這一側，最右邊那一串是崖下的斷拱廊）。圖的**上下**＝城堡的長軸 |

### 灰階對照（方便取色，但**不限於**這幾階 —— 線性，任何值都合法）

| 灰階 | 高度 | 大概是什麼 |
|---|---|---|
| `#000000` | 0 | 沒有建築（露出地面） |
| `#1A1A1A` | 33 | 最外圈的崖階 |
| `#333333` | 64 | 第二階 |
| `#4D4D4D` | 97 | 城牆、矮翼 |
| `#666666` | 128 | 側翼、扶壁 |
| `#808080` | 161 | 中殿的牆 |
| `#999999` | 192 | 正面、主體 |
| `#B3B3B3` | 225 | 塔身 |
| `#CCCCCC` | 256 | 高塔 |
| `#F2F2F2` | 304 | 中央尖塔的尖端 |

### 畫法（三句話）

1. **用平塗的階，硬邊，不要漸層**（漸層我讀得進去，但階數少比較好改、也比較好驗）。
2. **一塊就是一塊**：塔畫成圓、牆畫成長條、平台畫成多邊形。
   形狀複雜沒關係（我會逐列合併成方塊），但**邊要乾淨**，不要抗鋸齒糊掉的灰邊。
3. **不對稱是重點**。外廓圖上這座城是順著崖脊歪斜地攤開的，
   底圖那種同心的方框正是我要換掉的東西。

### ⚠ 常見的壞掉法（看到就退回重畫）

- **有透視**（近的大遠的小）→ 整張圖的比例尺就不是常數，量不出位置。
- **有光影**（受光面亮、背光面暗）→ 灰階被光照污染，讀出來的高度全錯。
  這張圖上**亮＝高**，沒有第二個意思。
- **抗鋸齒的柔邊**太寬 → 塔的邊緣會被讀成一圈斜坡。1~2px 的過渡沒關係。
- **改了畫布尺寸**或把城堡挪位置 → 與 `PLACES` 的座標對不上，整座會偏。
- 存成 JPEG → 8×8 的區塊雜訊在灰階上就是假高度。**一定要 PNG。**

## 三、交件 B（**校準用**，可有可無）：正立面剪影

**檔名**　`flight/Reference/belisar_elev.png`

**這一張 AI 產得出來**（它就是一張圖），交件 A 則不行（那是技術圖，見第五節）。

| 項 | 值 |
|---|---|
| 尺寸 | **1166 × 960 px**（寬＝高度圖的**高**；1166 ÷ 389 單位、960 ÷ 320 單位，同為 3 px/單位） |
| 內容 | **只有城堡本體**的剪影。⚠ **不要崖、不要樹、不要雲、不要地面** |
| 上色 | **純黑剪影 ＋ 純白底**，兩個顏色就好。沒有細節、沒有窗、沒有線稿 |
| 視角 | **正投影正立面**（從大門那一側正對著看），沒有透視、沒有消失點 |
| 對位 | 底邊＝地面（高度 0）；左→右 對應**高度圖的上→下**（同一條長軸） |

⚠ 對位不確定的話，**把兩張並排看一眼**：同一座塔在高度圖上的縱向位置，
應該等於它在立面圖上的橫向位置。對不上就是有一張轉錯方向。

## 四、交件之後我會做什麼

1. 寫 `flight/build_ruin.py`：讀高度圖 → **逐列合併成 `parts`**（相同高度的相鄰列
   併成一個方塊，同 `build_city.py` 的作法），輸出可以直接貼進 `RUIN_ART` 的資料。
2. 用立面圖**校準**：確認每一階的絕對高度、屋脊的位置與坡度。
3. 屋頂（`k:'gable'`）、錐頂（`cap`）、雉堞（`crenel`）照舊由程式端加上去 ——
   那三樣高度圖表達不了，但原語已經有了。
4. 跑一次既有的資料自檢（開口要包在牆內、零件不可以浮在半空）＋瀏覽器三距離實測。

## 五、⚠⚠ 這件事**不要丟給 GPT／Gemini**（交件 A）

高度圖是**技術圖**：它要的是精確的形狀、精確的灰階、零透視、零光影 ——
而圖像模型的每一個預設都與這四件事相反（它會加光影、加透視、把灰階畫成材質）。
實測過的同類教訓見憲法 §5「遺跡那 20 張」：**沒有同題材的底圖，它就退回大色塊**。

三條路，由 Ray 決定：

| | 誰做 | 成本 | 結果 |
|---|---|---|---|
| **A** | Ray 自己在底圖上改 | 大概 20~30 分鐘（就是塗灰色塊，不必畫得好看） | 剪影與外廓一致，**最準** |
| **B** | 只要交件 B（立面剪影），AI 產 | 一次生圖 | 我從剪影抽**逐欄高度**，正面會對；平面仍是我估的 |
| **C** | 不做 | 0 | 維持 ver -1164 的樣子 |

⚠ **B 比想像中有用**：現在最刺眼的「方」有一半在**正面的輪廓線**上，
而那正是立面剪影能定死的部分。要省力的話先做 B，看夠不夠再決定要不要 A。
