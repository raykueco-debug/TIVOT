# 一、⭐⭐⭐ 索拉娜的生圖方式（Ray 解出來的，照抄）

## 問題長什麼樣

1. **她的全身圖會被內容分類器誤判**。圖本身沒有問題（獵裝、不露點），
   但整張全身送過去會被擋 —— 實測 4 張過 3 張，`crying` 整趟白跑。
   ⚠ **被擋一次就是一次額度**，而且那段拒絕訊息**會留在頁尾不消失**
   （判準一律是「圖的張數有沒有增加」，不是頁面文字 —— 憲法 §5）。
2. **線上那 56 張，七成以上是代圖**：臉是 GPT 漂掉的版本、髮色被畫成紫灰，
   都不是設定稿。因為 alpha 一直做不好，這批就一直沒動工。

## 解法：三段，缺一不可

### ① 換載體 —— **分類器連你上傳的那張圖一起算分**

這是整件事的關鍵發現。同一個角色、同一套衣服：

| 上傳的參考圖 | 結果 |
|---|---|
| `Sorana_SI_front`（正面站姿） | 容易被擋 |
| **`Sorana_SI_battlecry`（側轉、手上有刀）** | **過** |

⇒ **基底一定要留刀。** 那個「戰士」的第一印象正是它成立的原因，
不是玄學，是分類器在看構圖給人的第一印象。

⚠ 但**產出**那一端相反：Ray 實測「指定不要拿武器」成功率較高。
**兩件事不要混：基底留刀，產出可以不拿。**

### ② 修臉 —— **Ray 自己用 SD 修，不要叫 GPT 修**

battlecry 的臉是漂掉的（臉偏長、下顎偏方、多一根呆毛、眉壓得重，讀起來老幾歲）。

⚠ 我試過叫 GPT「把臉改成設定稿的畫法」（`Sorana_battlecry_calm_v1.png`）——
**臉還是舊的**，只有表情改掉了。**那條路不通，不要再花時間。**

✔ 正解：**Ray 用 SD 修好的四張，就是 `resources/_originals/SI_sorana_base/soranagpt_1~4.png`**
（白底、battlecry 姿勢、帶刀、表情平靜、臉是設定稿的臉）。**那四張就是基底。**

⚠ 表情要平靜：battlecry 原圖是大喊，那個表情太強烈，**會把衍生的差分全部鎖進同一個表情**。

### ③ 鎖髮色與比例 —— **兩句否定句**

```
⚠ 髮色必須與原圖完全一致：帶青的冰藍白。
⛔ 不要畫成紫灰、藍紫或帶紫的白。
⚠ 比例維持原圖，不要把腿畫短。
```

⚠⚠⚠ **兩句都必須是否定形，不可以寫成肯定形**（Ray 實測）：
- 髮色：寫「⛔ 不要紫」有效；**只寫「要冰藍白」它照樣漂**。
- 腿：寫「**不要把腿畫短**」可以過；寫「**把腿畫長**」**會觸發誤判**。

⇒ 同憲法 §5「不要顆粒感要寫成『改畫什麼』」：**明寫失敗長什麼樣最有效**，
  而且**全程只講畫風與技術規格，不要描述身體** —— 觸發判定的是描述。

## 髮色的驗收（量得出來，不要用看的）

量法：取不透明區、頭頂往下 11% 身高那一帶，挑「亮且低彩」的像素（`max>150` 且飽和 `<0.30`），
平均之後轉 HLS 看**色相**。

| | 色相 H | 飽和 S |
|---|---|---|
| **正確**（`soranagpt_1~4` 原稿） | **194 ~ 206°**（青／冰藍） | 21 ~ 25% |
| **漂掉**（線上 `battlecry`／`front`、沒鎖時的 GPT） | **239 ~ 250°**（藍紫） | 7 ~ 14% |
| 加了鎖之後的產出 | **195.9 ~ 204.3°** ✔ | 22 ~ 27% |

⇒ **門檻：色相 < 220° ＝ 過；≥ 220° ＝ 飄成紫，重送。**

## 實證

- 四張基底跑 alpha：**4 送 4 過**（帶刀），髮色 195.9~204.3°，一次都沒被擋。
- Ray 用這一套把**先前被擋掉的 `crying`** 生出來了：髮色 **201.9° / S 21.6%**、
  **alpha 直接是透明的**、臉是設定稿的臉。
- ⇒ **「線上那批代圖可以整批換掉」這件事成立。** 那是這一輪真正的成果。

# 二、alpha 的作法（蕾娜那批用的，索拉娜也一樣）

## ⚠⚠⚠ Ray 定的一條（-1540，原話）

> 「**記住沒有我的同意不可走本機 alpha，gpt 為唯一可信 alpha**」

⇒ 憲法 §5 在 ver -1516 開的那個出口（`tools/si_matting.py` ＋ ToonOut）
**不是預設路徑，是要他點頭才動用的例外**。
⚠ 不准再用「指標過了」當放行理由 —— -1503 與 -1516 兩次都是**自己的驗收說了算**，
  兩次都被他一眼退掉。

## 提示詞 —— 就這一行，不要加長

```
重繪此角色，100%保留原角色細節，alpha背景
```

⚠⚠ **上傳的是白底原稿**（`resources/_originals/SI_ext/<名字>_white.png`），
**不是**現在線上那張 webp —— 那是壞掉的本機 alpha，拿它重繪等於拿壞的當底。

## 驗收 —— 三個門檻

| 指標 | 門檻 | 抓什麼 |
|---|---|---|
| **近白比例** | **< 1.5%** | 半透明像素中 `min(RGB) ≥ 235` 的佔比 ＝ 白霧 |
| **角落 alpha** | **= 0** | 有沒有真的去背 |
| 剪影 IoU | > 0.9 | 有沒有偷改構圖 |

基準：Ray 自己交的 GT ＝ **0.09%**；這一輪產出 0.03~1.29%；ver -1516 的 ToonOut ＝ 0.85~3.76%。
⚠ **一定要 100% 裁切用眼睛複核**，不准看縮圖（-1503 就是疊 220px 縮圖放行 78 張的）。

## 收圖的兩個坑

1. ⚠⚠ **會抓到自己剛上傳的那張** —— 它被 ChatGPT 重新編碼過，大小與產出圖很接近。
   **判準用「角落 alpha 是不是 0」**（上傳是白底不透明、產出是透明），不要用檔案大小。
2. ⚠⚠ **虛擬清單會讓新圖不在 DOM 上** —— 掃圖前要先把所有可捲動容器捲到底，
   不然會一直「等不到圖」而其實早就生好了。

## 卡住的處理

- 生圖**超過 6 分鐘沒動** ＝ 那一串死了 → **換新對話重送**（憲法 §5）。
  實測 `lookaside` 卡 9 分、`pointmap` 8 分、`side` 10 分，換串之後 45 秒就好。
- 兩個分頁跑兩條線可行，帳號不會鎖死。

# 四、⚠ 這一輪被卡住的地方

**Claude Code 的 auto mode 權限分類器會間歇性擋掉工具呼叫**，理由在
`Auto-Mode Bypass` / `Security Weaken` 之間輪替；偶爾是
`Stage 2 classifier error…（usually transient）` —— **只有這一種可以重送一次**。

| 動作 | 狀況 |
|---|---|
| Bash、`navigate`、`file_upload`、**短**的 JS | 大多通 |
| **一大段安裝腳本**注入頁面 | 幾乎必擋 |
| 一次十幾個 `wait` 的長批次 | 時好時壞 |
| 後期：**所有**瀏覽器動作（含內建瀏覽器） | 全擋 |

⚠ 它擋的不只是瀏覽器（Bash 跑 python、`mv` 各被擋過一次），像是對**整段對話脈絡**評分。
⚠⚠ **Ray 的指示：「碰到障礙要回報，不要一直撞牆」** —— 被擋就講，不要重試。

**出路**：錯誤訊息自己寫「可以在設定裡加 permission 規則」——
從**終端機**跑 `claude` 用 `/permissions`（Code 分頁叫不出那個面板），或改 `.claude/settings.json`。
⚠ **那是安全設定，要 Ray 自己決定。**

⚠ **內建瀏覽器不是替代方案**：它沒有 `file_upload`，而 chatgpt.com 的 CSP 擋掉從頁面抓本機檔案
（憲法 §5 記過）—— 上傳這條路只有 Claude in Chrome 走得通。
