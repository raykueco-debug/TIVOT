# 一、⚠⚠⚠ 產線的兩個新事實（**先讀這一段，不然會白燒一晚**）

## 1. GPT 出圖是 **5~15 分鐘**，卡住通常不是卡住

實測（-1414 那一晚）：同一批提示詞，有的 3 分鐘出、有的 **10 分鐘以上**才出。
「思考」兩個字掛在那裡、沒有停止鈕、`assistant` 訊息 0 —— **那不代表死了**。

- ⚠⚠ **不要照憲法「生圖卡住就換 session」的字面反射動作換串** ——
  那一條的前提是「卡住的那一串已經沒有產能」，而這一晚的實測是**它只是慢**：
  我等三分半就放棄的那一串，後來圖好端端地出來了（Ray 回報「飛行去背有出了」）。
  當晚白換兩串。
- ⇒ **正確作法：送出去之後放著，去做別的事，十分鐘後回頭收。**
  驗「有沒有真的送出去」照舊看 `[data-message-author-role="user"]` 的數量有沒有 +1
  ＋ 輸入框歸 0；送出去了就是在跑，不要重送。

## 2. ⚠⚠⚠ 圖橋的**表單 POST 那條路已經不通了**（改用 blob 下載）

`tools/imgbridge.py` 檔頭那段 CSP 實測是 **ver -1264** 記的，其中
「form-action 未設定 ⇒ 表單 POST 出去可以」**現在不成立**：送出去之後
**橋的 log 連一行 `ERR` 都沒有**（＝請求根本沒離開瀏覽器），而 chatgpt.com 的 CSP
裡確實沒有 `form-action` ⇒ 是**混合內容**擋的（https 頁面 → `http://127.0.0.1`）。

**改走這一條（實測可用，而且更短）：**

```js
const blob = await (await fetch(img.src)).blob();
const a = document.createElement('a');
a.href = URL.createObjectURL(blob); a.download = 'xxx.png';
document.body.appendChild(a); a.click(); a.remove();
```

→ 直接落在 `%USERPROFILE%\Downloads`。**「Chrome 擋自動下載」那句也過期了**
（至少對 blob URL 不擋）。
⚠ 圖橋還是要開著 —— **進料**那一路（`/grab`，走 `window.name`）沒有變。

## 3. ⚠ GPT 去背回來的 alpha **主體不是 255**
