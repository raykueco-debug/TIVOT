### 2. **ChatGPT 的圖可以程式化下載，不需要真人手勢**

上一輪交接寫的「複製圖片＋讀剪貼簿」那一套是**給 Gemini 用的**。ChatGPT 這邊
`fetch → blob → a[download].click()` 就直接落進 `~/Downloads`，**72 張一次都沒失敗**。

⚠ 兩個坑：
· 抓的時候**從最後往前找第一個 `size > 300000` 的**（頁面上還有我自己上傳的原圖）
· **產出圖與上傳圖的大小很接近** —— 收到之後比一次像素，我踩過兩次抓到自己上傳的那張

### 3. 去背：**亮度門檻永遠做不到，判準是「與背景色的距離」**

這一輪**換了三次判準**才對，完整推導在 `_ext_worklist.md` 第七節。結論：

```
bgc = 四角各 6px 的平均 RGB          # 逐張現算，實測 253.8~254.2，不可寫死 255
① max|袋平均RGB − bgc| <= 1.5        # 衣服的白有色偏，背景沒有
② 袋內像素 std        <= 2.0         # 衣服的白有漸層
③ 環(4px) 的 RGB std  <= 26          # 髮間空隙四周全是頭髮
```

⚠⚠ **為什麼亮度不行**：蕾娜髮間的**真背景**白袋是 250~253，
安雅白襯衫的**衣服**白袋是 250.7~253.2 —— **完全重疊**。
換任何一條亮度線都只是在「誰被犧牲」之間搬家（實測：248 → 諾薇兒白袍胸口被挖穿；
250.5 → 安雅白襯衫與白裙被挖穿）。

⚠⚠⚠ **驗收一定要疊深色棋盤看**：挖穿與正常版的「透明像素百分比」**一模一樣**
（安雅 read 兩版都是 57.9%）—— 數字看不出來，眼睛一看就知道。

會走到這條是因為 **ChatGPT 的產圖額度用完了**（畫面明寫「已達 Go 方案的圖像生成
要求上限，21 小時後重置」），而且帳號的檔案儲存空間也滿了、參考圖連上傳都上不去。
Ray 當場定案：「改用 gem，嚴格鎖畫風，神父圖不複雜，畫的時候就讓他容易去背，圖回來你來 alpha」。

### 1. ⚠⚠⚠ **取圖走 canvas 重繪 —— blob 抓不到，但 canvas 通**

憲法／舊交接寫的是「Gemini 的下載是死路，要走複製圖片＋讀系統剪貼簿」。
**還有第三條路，而且簡單得多**：

```js
const c=document.createElement('canvas');
c.width=img.naturalWidth; c.height=img.naturalHeight;
c.getContext('2d').drawImage(img,0,0);          // 同源，不會 taint
const b=await new Promise(r=>c.toBlob(r,'image/png'));
const a=document.createElement('a');
a.href=URL.createObjectURL(b); a.download=name;
document.body.appendChild(a); a.click(); a.remove();
```

· ⚠ **直接 `fetch(img.src)` 會失敗**（`TypeError: Failed to fetch`）—— Gemini 的圖是
  `blob:` URL，屬於別的 context。**canvas 重繪繞過了這件事。**
· 實測 10/10 成功，不需要真人手勢、不需要剪貼簿、不需要分頁在前景就能抓
  （⚠ 但**送提示詞**仍然需要分頁在前景 —— 憲法那條「hidden 分頁整頁渲染不出來」沒變）。
· ⚠ 拿到的是**畫面上那張**的解析度 —— Gemini 的輸出上限是**長邊 1024**（實測 687×1024）。

### 2. 送出：**合成 Enter 有效**（憲法那條成立），連新對話的首頁也有效

### 3. ⚠⚠ Gemini 會把這兩件事畫錯，要明寫「**不是什麼**」

| 要的 | 它第一次畫成 | 有效的寫法 |
|---|---|---|
| `smiley eyes`（雙眼笑成 ＾＾） | **單眼眨眼** | 「**左右兩隻眼睛都要**笑成往上彎的弧線」「⚠ **不是眨眼**：不要一隻閉一隻睜，**兩隻眼睛要一模一樣**」 |
| 「微笑**閉嘴**」 | 張嘴露牙 | 「**嘴唇完全閉起來**，只有嘴角往上揚 —— **不要張嘴、不要露出牙齒、不要看到嘴巴裡面**」 |

⚠ 同 §5 那條「不要顆粒感要寫成『改畫什麼』」：**明寫失敗長什麼樣，比形容成功長什麼樣有效**。

### 4. 「讓它容易去背」要寫進提示詞（Ray 指定）—— 實測有效

```
· 純白 #FFFFFF 的平塗背景，整張圖的背景完全均勻
· 不要畫地面、影子、光暈、漸層、暈影、紋理、邊框或任何裝飾
· 角色輪廓的邊緣要乾淨銳利（清楚的深色描邊），不要白霧、不要發光邊、不要模糊過渡
```

實測六張**一個白袋都不用挖**（灌水就乾淨），去背零瑕疵。
⚠ 但它的背景是 **252** 不是 ChatGPT 的 254 —— 所以去背的 `bgc` **一定要逐張現算**
（§七那條「不可寫死 255」在這裡救了一次）。

### 5. 尺寸與色偏

· **687×1024 → 1024×1536**：等比放大到高 1536（寬變 1030），再置中裁到 1024 寬。
· **色偏幾乎沒有**（ΔV +0.004 / ΔS −0.03），而且那個 S 的差是**污漬被移掉**造成的，
  不是 Gemini 推高飽和度。⇒ **這一批不必校色**（憲法門檻是 ΔV>0.05 或 ΔS>0.06）。
  ⚠ 不要把「Gemini 一律推高飽和度」當成每次都要校 —— **量過再決定**。

### 6. ⚠ 已知瑕疵

· **六張的袍子寬度與長度略有不同**（聖帶位置也是）—— Gemini 是逐張重畫的，
  在遊戲裡連續切換差分會看得出「衣服在動」。臉的位置與大小是一致的（取景值六張全同）。
· ⚠⚠⚠ **臉比底圖年輕、臉型偏寬、鬍子變短變淡、疤幾乎看不見** —— 這是 **Gemini 的天花板，
  不是累積漂移**。我為此**特地開新對話重新上傳底圖驗證過**（憲法那條「一張圖一個新對話」）：
  新串版與同串第 11 張的臉**幾乎一模一樣**。⇒ 換串救不了。
  **✔ Ray -1503 定案：「就先用這個交件吧，配角而已」—— 不重跑，這一批結案。**
  ⚠ 日後他若升格成有戲份的角色，再用 ChatGPT 重跑一輪會緊得多（提示詞照這一節抄）。
· ⚠⚠ **「閉嘴」Gemini 連錯三次**。有效的寫法是把嘴**當成一條線來描述**，並列出禁止項：
  「**畫成一條往上彎的閉合嘴線**（上下嘴唇合在一起，只有兩端嘴角往上翹）」＋
  「⛔ 絕對不要：張開的嘴、露出牙齒、看得到口腔或舌頭、橢圓形或半月形的開口 ——
  **這一張的嘴裡不可以有任何東西看得見**」。
· ⚠ 第二版的**袍子比底圖短一截**（到小腿，底圖到腳踝），聖帶也短一些。
