## 三、玩家實際下載量（逐畫面載入，鐵律 13）

照鐵律 13，每過一道讀取頁只載那個畫面要的東西。玩完一輪的**累計**下載 ≈ 上限 595 MiB 扣掉「這一輪不會碰到的」：

| 扣除 | 約 MiB | 理由 |
|---|---:|---|
| 飛行頁資料夾裡程式沒引用的 | −72 | `flight/city/*_iso.png`、`*_topdown*.png` 這類製作來源（62.7 MiB 沒有任何程式提到檔名）＋試玩用不到的天空怪精靈圖（25 MiB） |
| 卡耶爾夢境的隨機池 | −25 | 池子 16 場，一趟大約碰到一半（夢境動畫共 62 MiB） |
| 沒看到的時段差分 | −8 | 背景共 20.5 MiB，一趟只會看到其中一兩個時段 |
| 挑戰（不玩就不載） | −2 | |
| **合計** | **≈ 490 MiB** | 再扣掉城鎮資料裡試玩之後章節的立繪表情（下面的漏算風險 1），落在 450～500 MiB |

- 單一道門最重的是**進卡耶爾夢境**和**空賊戰**（各要一批群戰動畫，數十 MiB 等級）；首頁只有約 1.6 MiB。
- ⚠ 這是**下載量**，不是記憶體量。記憶體看的是動畫格解碼後的大小，另見效能稽核。

## 四、量法（靜態收集）與漏算／多算的風險

**沒有用 `tools/challenge_build` 的追蹤法**：那一套要實際把整輪試玩跑過一遍並錄下資源清單，試玩範圍太長（九場主戰＋三張城鎮圖＋飛行），不實際。改用**靜態字串閉包**：

1. 母集合＝`offline_list.json`（`tools/offline_list.py` 產的離線包，已排除工作素材）。
2. 起點：`MAIN_SCRIPT` 全部 7 幕、`TOWNS.capital／northport／canyon`、`DINE`／`OUTING`、飛行戰四張卡、`tutorial`、挑戰（`lineup`／`intruder`／挑戰搭檔／監察官）、首頁的 `HOME_IMG`／`HOME_SFX`／`bgm_home`、戰鬥共用的 `ASSETS` 前綴（`weapon_`／`switch_`／`sfx_`／`se_`／`vo_`…）。
3. 把資料裡的每個字串展開，查表到收斂為止：戰鬥卡 → 敵人卡 → 群戰編組 → `ENEMY_IDLE`／`ATK`／`DELAY`…（動畫資料夾整個收）→ `ASSETS` 鍵 → 檔名；背景自動帶五個時段差分、立繪自動帶眨眼差分（`_closed`／`_half`）；劇情拍上的 `portrait{char,expr}` 只收那一張表情。
4. 另外整包算：程式層（js/html/css/json/字型）、`flight/` 整個資料夾、`resources/audio/se`／`vo`；runtime 程式碼（modules／main／index／style）裡直接寫死檔名的素材也收。
5. `frame_00` 這種同名超過 3 個的檔名不拿來配對（不然會把整個動畫庫拉進來）。

**多算（所以是上限）**
1. **城鎮資料不分章節**：`TOWNS.capital／northport` 裡也掛著試玩之後回帝都、回北泊的段落，那些段落用到的立繪表情、背景也被算進來（立繪 renna 118 張、sorana 99 張偏多就是這個）。要精算得照旗標模擬章節，這一版沒做。
2. `flight/` 整包算（含 62.7 MiB 沒被引用的製作來源，見第三節）。
3. 音效／語音整包算（只有 12 MiB，不值得細分）。

**漏算**
1. **程式碼用字串組出來的路徑**（例如 `` `ef_${x}.webp` ``）：只有「完整檔名寫在程式裡」的才抓得到。受擊特效、UI 小圖可能漏幾 MiB。
2. 飛行頁用字串組的路徑：`flight/` 整包算，所以不會漏；它在 `resources/` 底下的引用則靠檔名配對。
3. 劇情演出層組名字的退路（例如插圖的時段候選）：已經帶五個時段，只漏「大小寫不同的同名檔」。

⇒ 真正上線切試玩版時，還是要照 challenge_build 的作法把精簡後的資料實跑一輪，才算數。這份是**架構決策用的量級**：程式約 10 MiB／約 120 檔，素材約 0.5～0.6 GiB／約 6,300 檔，單檔都在 5 MiB 以下。
